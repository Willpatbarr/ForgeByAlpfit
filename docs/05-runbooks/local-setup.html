Local Setup

What this is: the exact steps from a fresh clone to a running app on your machine, fastest path first — read this before touching anything else.

Prerequisites

RequirementDetail
Flutter SDKInstall the Flutter SDK for your platform (includes the Dart SDK). Chrome is the target for the fastest run, so a Flutter install with web support enabled is what you need.
Dart constraint^3.9.2 — from pubspec.yaml:7 (environment: sdk: ^3.9.2). Whatever Flutter version you install must ship a Dart SDK satisfying this.
ChromeRequired for the flutter run -d chrome path below.
GitTo clone the repo.

Setup steps

  1. Install the Flutter SDK following Google's official install guide for your OS, then confirm it's on your PATH. 
    flutter --version
    Verify: the printed Dart SDK version satisfies ^3.9.2 (i.e. is 3.9.2 or newer, below 4.0.0).
  2. Run Flutter's own environment doctor and resolve anything it flags as missing for your target platform (Chrome/web at minimum). 
    flutter doctor
    Verify: the Chrome line shows a checkmark. Android/iOS toolchain warnings can be ignored if you only intend to run on web today.
  3. Clone the repository. 
    git clone https://github.com/Willpatbarr/ForgeByAlpfit.git
    Verify: a ForgeByAlpfit/ directory now exists with a forge_senior_project_version/ subfolder inside it.
  4. Change into the app root — it is a subfolder of the repo, not the repo root. This is the step people skip and then get confusing "no pubspec.yaml found" errors from. 
    cd ForgeByAlpfit/forge_senior_project_version
    Verify: ls pubspec.yaml succeeds from your current directory.
  5. Fetch Dart/Flutter package dependencies. 
    flutter pub get
    Verify: command exits with no red error text; a .dart_tool/ directory now exists.
  6. Run the app in Chrome — the fastest path to something on screen, no platform-specific build tooling required. 
    flutter run -d chrome
    Verify: Chrome opens automatically and the Forge login/register screen renders.

Firebase config already committed

No separate Firebase setup step is needed to run locally. lib/firebase_options.dart, android/app/google-services.json, and ios/Runner/GoogleService-Info.plist are already committed to the repo and point at the real forge-by-alpfit Firebase project.

FileWhat it actually is
lib/firebase_options.dartClient identifiers, including the web API key. Not a server secret by design — Firebase web API keys are meant to be embedded in shipped clients.
android/app/google-services.jsonAndroid client registration for project forge-by-alpfit.
ios/Runner/GoogleService-Info.plistiOS client registration for the same project.

What actually governs who can read or write data is Firestore security rules, not secrecy of these files. Anyone with the API key can only do what the rules allow — see deploy.html for the current state of those rules, including a known open hole being fixed in Milestone 1.

Footgun: local runs hit the real production Firestore. There is no Firebase emulator configured and no separate development project. Every write you make while developing locally — test events, test goals, test messages — lands in the same Firestore data real users would eventually see. There is no sandbox to break instead.

Repo size after building

DirectorySizeNote
forge_senior_project_version/build/1.7 GBCreated by flutter run / flutter build. Not in git — ignored.
forge_senior_project_version/.dart_tool/621 MBCreated by flutter pub get. Not in git — ignored via the root .gitignore.

A fresh git clone is small. The first flutter pub get and flutter run grow the working copy by roughly 2.3 GB combined — budget disk space accordingly before you start.

What To Do Next

  1. Run the six setup steps above in order; do not skip the cd forge_senior_project_version step.
  2. Remember every local write hits production Firestore — do not use throwaway-looking test data you'd mind other people seeing.
  3. Once the app runs, read deploy.html before attempting to ship any change you make.
