Clone to running

  1. Install Flutter on the stable channel and put it on your PATH. On macOS the least painful route is the official tarball from flutter.dev, unzipped somewhere permanent like ~/development/flutter. Avoid installing Flutter through Homebrew — upgrades fight with flutter upgrade.
  2. Confirm the version.
    flutter --version
    You want Flutter 3.38.0 or newer on stable, carrying Dart 3.10 or newer. If it's older, run flutter channel stable && flutter upgrade. If it's much newer and something breaks later, that's a real possibility to note — nothing in this repo pins an upper bound.
  3. Run flutter doctor.
    flutter doctor -v
    Fix everything that isn't a green check for the platform you intend to run on. You can ignore red marks for Chrome/web, Linux and Windows toolchains — per D3, iOS and Android are the only supported targets.
    Done when: the Flutter, Xcode (or Android toolchain), and connected-device lines are all green.
  4. Accept the Android licences (Android only).
    flutter doctor --android-licenses
    Answer y to every prompt. Skipping this is the most common reason a first Android build fails at Gradle.
  5. Clone the repo.
    git clone <the ForgeByAlpfit repo URL> && cd ForgeByAlpfit
    The repo is private — you need to be a GitHub collaborator first. See github.html and onboarding.
  6. Move into the app directory.
    cd forge_senior_project_version  # or: cd app
    Every remaining command runs from here. flutter commands run from the repo root will fail with "no pubspec.yaml found" — there is no pubspec at the root.
  7. Fetch packages.
    flutter pub get
    Eight direct runtime dependencies, all public on pub.dev. No private package registry, no auth token, no .env file.
    Done when: it prints "Got dependencies!" and .dart_tool/ appears.
  8. Install iOS pods (iOS only).
    cd ios && pod install && cd ..
    Usually flutter run does this for you. Do it manually the first time so pod failures show up here rather than buried in a build log. On Apple Silicon, if it fails, try arch -x86_64 pod install.
  9. Confirm you have Firebase project access. The app talks to the live Firebase project forge-by-alpfit. You do not need credentials to build — the config is already committed (see below) — but you cannot see data, read rules, or debug an auth failure without console access. Ask William to add your Google account to the project. Details and the role to ask for: firebase.html.
    Anything you create while running locally lands in the real, shared project. There is no staging project — that's a deferred item. Use a throwaway account, not a real user's.
  10. Start a device and run.
    TargetStart the deviceRun
    iOS simulatoropen -a Simulatorflutter run -d iPhone
    Android emulatorflutter emulators --launch <id> (list with flutter emulators)flutter run -d emulator-5554
    Either, interactively—flutter devices then flutter run and pick
    First Android build pulls the whole Gradle toolchain and can take 10–15 minutes. First iOS build compiles the Firebase pods and is similarly slow. Neither is a hang.
    Done when: the app launches to the Login screen — not the Feed. The router redirects unauthenticated users to /login.
  11. Prove it worked — the real verification. See the next section. Building is not the same as working; the app can compile perfectly and still fail at the first Firestore read.

Proving it worked

A green build proves the toolchain. It proves nothing about Firebase. Do all four:

  1. Register a throwaway account. On the Login screen tap through to Register, choose account type User, and sign up with an address you don't care about. Password must be at least 6 characters.
    Verified when: registration succeeds and you land on the Feed, and a new document appears under users/ in the Firestore console.
  2. See the Feed render. It will be sparse on a brand-new account — that is correct, not broken. What matters is that it renders without a red error screen and without an infinite spinner.
    Verified when: the Feed's cards draw and the bottom navigation shows all five tabs.
  3. Write something. Tap Create, make a basic event with a title, a start time and an end time, and save it.
    Verified when: the event appears on the Calendar tab and a document appears under users/<your uid>/events/ in the Firestore console. This is the step that proves auth, rules and Firestore writes are all working together.
  4. Restart and confirm persistence. Fully quit the app on the simulator and relaunch.
    Verified when: you're still signed in and the event you created is still on the calendar. This mirrors the project's own definition of a fulfilled requirement — data correctly saved and displayed across app restarts.
Set expectations before you go exploring. Several screens look finished and are not — the calendar filter popup shows hardcoded names, the DM Attend/Decline chips don't persist, and four sections of the Create hub are empty by construction. That is Milestone 2, not a broken install. Full list: features.

Firebase config already in the repo

You don't need to generate or download anything. These files are committed and git-tracked:

FileCovers

$APP/firebase.jsonPoints the Firebase CLI at firestore.rules, firestore.indexes.json, storage.rules
  • firebase_options.dart — the linux branch throws UnsupportedError. That is expected; Linux is not a target.
These are not leaked secrets. Firebase client config identifies the project; it is not a credential. Committing it is normal and correct for a Firebase client app, and there is nothing to rotate. What actually controls access is firestore.rules — and that file currently has a real hole, which is why Milestone 1 exists. Fix the rules; leave the config alone.

Troubleshooting

The failures you will actually hit, in rough order of likelihood.

SymptomCauseFix
Could not find a file named "pubspec.yaml" You're at the repo root. There is no pubspec there. cd forge_senior_project_version (or cd app).
The current Dart SDK version is X. Because … requires SDK version ^3.9.2 Flutter is older than 3.38. flutter channel stable && flutter upgrade, then flutter pub get again.
Gradle fails with a licence error on the first Android build Android SDK licences not accepted. flutter doctor --android-licenses, accept all, rebuild.
pod install fails, or iOS build errors inside a Firebase pod Stale Pods, or CocoaPods repo out of date. cd ios && pod repo update && pod install
App builds, launches, then shows a red error screen on the Feed Almost always a missing Firestore composite index, or the nullable-startAt crash path. Read the console output — Firestore prints a "create index" URL.
A gym channel screen tells you to run firebase deploy --only firestore:indexes A missing index — and the app shows CLI text as end-user UI. Deploy the indexes — see deploy.
PERMISSION_DENIED reading or writing Firestore Your local rules and the deployed rules have diverged, or you're signed out. Check you're signed in, then diff $APP/firestore.rules against the console.
MissingPluginException from image_picker on web Known — there is a shim (register_web_image_picker.dart) for it. Don't chase it. Web is not a supported target (D3). Run on a simulator instead.
flutter analyze is clean but the code is clearly not Correct, and it's the problem. analysis_options.yaml is one line, with strict-casts off. Don't cite a clean analyze as evidence of anything until M1 turns strict-casts on.
flutter test says no tests found Correct. There is no test/ directory anywhere in the project. Creating it is the first testing issue in M1.
Build succeeds but the app on device is named forge_senior_project_version Correct today. Scaffold identifiers and com.example.* bundle IDs. Fixed in M3 — don't patch it ad hoc.
Everything is weird after switching branches Stale build artifacts. flutter clean && flutter pub get, and on iOS delete ios/Pods too.
  • pod install failures — if pod repo update doesn't clear it, delete ios/Pods and ios/Podfile.lock, then flutter clean && flutter pub get and retry.
  • Red error screen on the Feed — if it isn't a missing index, it's the crash path: an event saved without a start time hits an unchecked as Timestamp cast. A known defect, fixed in M1.
  • Gym channel screen showing CLI instructions — not a joke; the app really does ship developer instructions as end-user UI when an index is missing. Removing that screen is an M2 issue.
  • PERMISSION_DENIED — the repo file is the source of truth; the console may be behind. Redeploy from deploy rather than editing rules in the console.
  • Wrong app name on device — changing the bundle ID requires re-registering the Firebase apps, so do it once, in M3, deliberately.

What To Do Next

  1. Complete all four checks in Proving it worked — especially the restart. Building is not working.
  2. Read the architecture overview before opening any file, so you don't mistake the empty core/ scaffold for work in progress.
  3. When you're ready to push a change out, go to deploy.html — and note that the Firestore rules deploy is separate from any app build and is the one people forget.
