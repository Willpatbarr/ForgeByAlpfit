Decisions

What this is: every decision behind the product, tagged LOCKED, DECIDED, PROPOSED, or DEFERRED, with the rationale and — for anything deferred — the trigger that reopens it.

Needs William's review

These three PROPOSED calls are where this plan is a default, not a decision. Everything else on this page follows from the notes or the code; these three are taste calls made in William's absence.

1. One consumer app, not the three-product AlpFit business

Trade-off: the earliest, undated brainstorm describes three separate products — consumer app, gym-management software, trainer software — but every later formal Proposal and Requirements doc scopes to one Flutter app in which "gym" is an account type, not a product. Direction of travel favors one app; this default is in force, but it is a question about what the product fundamentally is, and that call belongs to William.

2. Web + Android beta, iOS deferred

Trade-off: Web is already deployed once, costs nothing, and has no review queue; Android is a $25 one-time fee with an internal testing track and no review delay; iOS is $99/year plus real review latency. Picked web-first because it is the fastest, cheapest path to real users — flips if most rec-center testers turn out to be on iPhone.

3. Sentry vs. Firebase Crashlytics

Trade-off: Crashlytics is free, unlimited, and already inside Firebase — the more consistent choice, which William weights heavily — but its Flutter web support is poor, and web is the beta channel. Sentry gives one dashboard across web and mobile on a 5k-errors/month free tier; picked because live-surface coverage beats stack tidiness, flips if the beta ends up mobile-only.
