Forge App - Goal Class Design Specification
Overview
This document defines the structure and behavior of the Goal class for the Forge app.  A Goal represents a user-defined objective that requires completing a set number of check-ins within a repeating time period (reset period). Progress resets each period, and historical performance is stored.  This design focuses on: - Period-based progress (NOT scheduled timestamps) - Clean data modeling for Flutter + Firestore - Extensibility for future goal types 
Core Concept
Each Goal: - Has a start and end date - Requires a fixed number of check-ins per reset period - Tracks progress within the current period - Stores completed period history - Becomes archived after the end date 
Goal Class Definition
class Goal {   final String id;   final String userId;    String name;   String description;    DateTime startDate;   DateTime endDate;    int requiredCheckupsPerPeriod;   ResetPeriod resetPeriod;    int currentCheckupsCompleted;   DateTime currentPeriodStart;   DateTime currentPeriodEnd;    GoalStatus status;    List<GoalPeriodRecord> periodHistory;    DateTime createdAt;   DateTime updatedAt; } 
Enums
enum ResetPeriod {   daily,   weekly,   biweekly,   monthly, }  enum GoalStatus {   active,   archived, } 
GoalPeriodRecord Class
class GoalPeriodRecord {   final DateTime periodStart;   final DateTime periodEnd;   final int requiredCheckups;   final int completedCheckups;    double get completionRate {     if (requiredCheckups == 0) return 0;     return completedCheckups / requiredCheckups;   } } 
Methods
void checkIn() void uncheckIn()  double getCurrentProgress() double getOverallCompletionRate()  bool isCurrentPeriodComplete() bool isActive() bool isArchived()  void archive() 
Behavior Rules
- Check-ins increment progress within the current period - Progress cannot exceed requiredCheckupsPerPeriod - At reset, current progress is stored in history - A new period begins automatically - When endDate is reached, the goal is archived 
Validation Rules
- name cannot be empty - requiredCheckupsPerPeriod > 0 - endDate must be after startDate - endDate must be within 1 year of startDate - cannot check in if goal is archived - currentCheckupsCompleted cannot exceed required amount 
Widget Usage
Display: - Goal name - Progress ring  Progress calculation: currentCheckupsCompleted / requiredCheckupsPerPeriod 
Architecture Recommendation
The Goal class should be a DATA MODEL only.  Business logic like: - Resetting periods - Archiving expired goals  Should be handled by a separate GoalService class. 
Firestore Notes
- Store enums as strings - Use DateTime <-> Timestamp conversion - Implement toJson() and fromJson() methods
