Forge
William Barr

A workout app focused on helping people connect with others that attend their same gym. By connecting newer and older members, gyms can foster an inclusive and supportive environment, attracting more new members. Friends can coordinate and support each other’s goals. Together everyone can be more active and achieve the goal of being healthier.














Introduction
Purpose
	There is a barrier of intimidation and self-consciousness that keeps people from starting a fitness journey. Many times I have heard from peers that they would love to start working out and exercising, but they are scared of looking dumb or that they don’t know what to do. These same people, if they eventually attend a gym consistently, admit that they should’ve never worried in the first place. Almost every person in a gym is more than willing to get to know and help anyone else.
	The goal of this app is to connect people. When we make genuine human connections we feel safer. If people feel safer they are more likely to try new things that can previously be intimidating, thanks to the support of those around them. By having a place where new members can find others and see how they truly care about everyone’s journey I believe more people will start working out and getting healthier. 
	This app will allow people to interact with members of their same gym and other people they meet in order to make friends that they can plan goals, workouts, and other events with.
Requirements
Must Have Requirements
Users can:
	•	Create account as either a member or gym
	•	Login and logout
	•	View updates from friends and gyms
	•	View a dashboard with widgets connecting to friends, events, and goals
	•	View a calendar with a daily, multi day, and monthly view
	•	View events scheduled in each view
	•	Edit events scheduled by tapping on one
	•	Create events of two kinds; basic and workout
	•	Invite friends to either kind of event
	•	Set events to different levels of visibility, including public or private
	•	Add start and end time and date to events
	•	Add notes to events
	•	Add exercises to workout events
	•	Add a number of sets for each exercise in a workout event
	•	Add a number of reps and weight for each set in an exercise
	•	Add a location of which gym a workout event will happen at
	•	Search for other gyms and users
	•	Add friends and gyms
	•	View profile page of other users
	•	View community page of a gym and the social channels hosted by that gym
	•	Participate in social channels of gyms user is a member of
	•	Message friends and gyms directly
	•	Create and manage community and social channels if a gym account
	•	Moderate posts and interactions in community if a gym account
	•	Remove from or accept users into a community if a gym account
	•	Edit account name
	•	Edit account contact info
	•	Edit account profile photo
	•	Manage friends and gyms lists

Overview of the Product
Workflow
The Forge application follows a social-first workflow centered around events, workouts, and gym communities.
User Onboarding
A first-time user is presented with a Sign In / Sign Up screen.  During sign-up, the user provides:
	•	username 
	•	email 
	•	name 
	•	password 
	•	account type (member or gym) 
Account type selection occurs during sign-up. Gym accounts may follow a different onboarding flow, though this is not fully defined at this time.
Primary Navigation and Daily Use
After authentication, users are taken to the Feed page, which serves as the primary landing screen for returning users.
From the feed, the most common user actions are:
	•	creating a new event 
	•	viewing events and updates from friends or gyms 
Discovering Users and Gyms
Users navigate to Social → Search to discover other users or gyms.  Joining a gym community may be instant or require approval, depending on the gym’s configuration.
Event Creation and Management
Users create events by tapping the Create button located in the bottom-right corner of the app.
Event creation workflow:
	•	User selects an event type (basic or workout) 
	•	User enters required information: 
	•	event name 
	•	start date/time 
	•	end date/time 
	•	Optional information may be added 
	•	User taps Create Event, at which point the event is saved 
Workout events allow exercises, sets, reps, and weights to be defined during creation and edited later.
Event Visibility and Consumption
Public events created by friends or gyms appear on a user’s calendar and feed, provided the event owner is not filtered out in the calendar view. Users can view events across daily, multi-day, and monthly calendar views.
Social Interaction
Messaging and social interactions occur under Social → Messages. Feed updates are triggered when:
	•	a friend or gym creates a public event 
	•	a gym posts an update to its members 
Gym Accounts
Gym accounts can host communities and publish posts to their members.  Community management and moderation workflows are not yet fully defined and will be refined during development.
Session Completion
A user session is considered successful when the user has:
	•	created or edited a workout or event 
	•	viewed updates in their feed 
	•	interacted with another user or gym community

Resources
Forge is built using a client-server architecture. The frontend is a Flutter mobile application. Backend services are provided by Firebase, including Authentication, Firestore for data storage, and Cloud Storage for media. The app communicates with backend services over HTTPS using Firebase SDKs.
Data at Rest
User data is stored in a cloud-hosted NoSQL database. This includes authentication-related data (user ID, account type), user profiles, gym profiles, events, workouts, messages, and community posts. Data is persisted as structured documents to support real-time updates and efficient querying. Media such as profile images is stored separately in cloud storage and referenced by the database.
Data on the Wire
Data is transmitted between the mobile client and backend services using secure HTTPS connections. The application uses authenticated requests to send and receive data such as account information, events, calendar updates, messages, and community interactions. All data is serialized and transmitted using structured formats supported by the backend SDKs.
Data State
The application follows a synchronized state model. User actions such as creating events, editing workouts, or sending messages update local application state immediately and are then written to the remote database. When remote data changes, updates are propagated back to connected clients in near real time. This ensures that the feed, calendar, and messaging views remain consistent across sessions and devices.
HMI/HCI/GUI
The Forge application uses a mobile-first graphical user interface designed to reduce intimidation for new gym members while keeping frequent actions easy to access. Navigation is organized using a bottom navigation bar that provides quick access to the Feed, Calendar, Social, and Profile sections.
Primary interactions such as creating events are emphasized through clearly visible action buttons. Calendar views support daily, multi-day, and monthly layouts, allowing users to easily view scheduled events. Forms for creating workout events progressively introduce additional inputs, such as exercises, sets, and weights, only when needed to avoid overwhelming users.
Verification
Each requirement will be verified through direct interaction with the running application. A requirement is considered fulfilled when the expected behavior occurs through the user interface and the resulting data is correctly saved and displayed across app restarts. A requirement will not be fulfilled if an action fails, produces incorrect or missing data, or does not persist across restarts. Stretch requirements are verified in the same manner when implemented and accessible through the UI.
