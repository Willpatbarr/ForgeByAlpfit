Apple Developer Program

What this is: the runbook for iOS distribution — deliberately not adopted yet. This page exists so the trigger, the cost, and the setup gotchas are all known before William decides to spend the $99.
Deferred, not rejected: T2 When it hurts. Web-first + Android beta reaches "someone else can use it without me present" faster and for less money. iOS is one decision away, not off the table.

What & why

The Apple Developer Program is the only way to run TestFlight or publish to the App Store — there is no side door. It costs $99/year, recurring, which is exactly why it loses to Google Play's $25 one-time fee for a beta that hasn't proven it needs iPhone testers yet.

OptionWhy it lost / won (for now)
Web + Android only (current plan)Wins for T1. $0 web, $25 one-time Android, no recurring cost, no review wait on internal testing.
Apple Developer ProgramLoses today on cost asymmetry alone: $99 every year versus Play's $25 once. Deferred until there's a concrete reason to spend it.

Adoption trigger

T2 When it hurts — the plan is explicit that this inverts the instinct in the original notes (which budgeted an Apple account by default). Adopt it when either of these happens: beta feedback shows testers are iPhone-heavy, or William decides he wants App Store distribution regardless of tester mix.

Setup steps

  1. Decide Individual vs Organization account before enrolling. Worth deciding deliberately: an Individual account publicly shows William's personal legal name on the App Store listing; an Organization account hides that but requires a D-U-N-S number to enroll.
  2. Enroll in the Apple Developer Program and pay the $99/year fee.
  3. Change PRODUCT_BUNDLE_IDENTIFIER from com.example.forgeSeniorProjectVersion to a real reverse-domain id matching Android's, e.g. com.alpfit.forge. Painful to change later: same category of problem as the Android applicationId — best fixed once, deliberately.
  4. Re-register the iOS app in the Firebase console under the new bundle id and regenerate GoogleService-Info.plist.
  5. Build in-app account deletion before submitting anything for review — App Store Review Guideline 5.1.1(v) requires it for any app with account creation, and this work is already scheduled in Milestone 1.
  6. Set up TestFlight internal testing (up to 100 internal testers, no review required).
  7. If testers outside the Apple Developer team are needed, submit the build for Apple's Beta App Review before external TestFlight distribution opens.
  8. Verify: install the app via TestFlight on a real iPhone and confirm it opens against live Firestore.

Real secrets — signing certificates, private keys, API tokens — are never committed to the repo.

Escape hatch

Lock-in: Medium

QuestionAnswer
What lives only hereThe App Store listing, TestFlight build history, and any accumulated App Store reviews once published.
Export pathThe Flutter codebase is portable — nothing about the app's logic depends on Apple's tooling. Dropping the program means the iOS build stops distributing, not that code is lost.
Migration costMedium — losing the $99/year buys back nothing already spent, and re-enrolling later re-triggers the same bundle-id and TestFlight setup. Mostly an admin cost, not a rewrite.

Cost & scale checkpoints

ScaleExpected Apple cost
~10 users$99/year flat — TestFlight internal testing covers this comfortably.
~100 usersStill $99/year flat. At the top of TestFlight's internal tester range, external testing (Beta App Review) may be needed, but the program fee doesn't change with usage.
~1,000 usersStill $99/year flat — Apple does not charge more for a free app's downloads, only the flat annual program fee.
