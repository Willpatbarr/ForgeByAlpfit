Linear LOCKED T0 Now

What this is: the single write target for all Forge planning — issues, statuses, and labels live here, not in GitHub Issues.

What & why

Linear is William's planning UI: every task, bug, and improvement for Forge is tracked here as an issue. It was chosen because it is already William's standing tool, the workspace and team already exist, and it keeps planning cleanly separated from GitHub's code-and-docs role.

AlternativeWhy it lost
GitHub IssuesWould duplicate Linear if both were written to. Per the brief (§9 Q4), GitHub Issues stays the read side, not the write target — Linear writes are one-way unless sync is later enabled.
A plain text/markdown TODO fileNo statuses, labels, or multi-team structure; does not scale past a solo dev's memory.

Adoption trigger

LOCKED T0 Now — already adopted. Workspace WillieWorkspace exists; team ForgeByAlpfit already exists (created 2026-08-15).

It is T0 because planning work starts immediately, same reasoning as GitHub for code — there is no lower tier for "where does the work get tracked."

Setup steps

  1. Confirm workspace WillieWorkspace and team ForgeByAlpfit exist. They already do.
  2. Confirm default statuses are in place: Backlog, Todo, In Progress, Done, Canceled, Duplicate. These are Linear's defaults and require no setup.
  3. Confirm default labels exist: Feature, Bug, Improvement.
  4. Add the plan's area and tier labels on top of the defaults (for example, T0/T1/T2 matching this doc set's tier system). Label taxonomy is cheap to add now, painful to retrofit onto 200+ existing issues later — do this before the issue count grows.
  5. Leave GitHub Issues Sync off unless a deliberate decision is made to turn it on (see Escape hatch and Teammate delta below for why).
  6. Verify: create one test issue in the ForgeByAlpfit team, confirm it lands in Backlog with the Feature/Bug/Improvement label options available, then delete the test issue.
