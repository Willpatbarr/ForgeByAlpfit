Forge docs / 03-services / Cloudflare Pages

Cloudflare Pages T1 Before first user

What this is: hosting for the docs/ folder only, rendered as a static site on every push — it does not touch the Forge app, which stays on Firebase Hosting.
Boundary, stated plainly: Cloudflare Pages serves this documentation site. The Forge app is served by Firebase Hosting, unchanged. These are two different deployments of two different things — do not point Cloudflare Pages at the Flutter build output, and do not point Firebase Hosting at docs/.

What & why

Cloudflare Pages builds and serves the docs/ folder as a static site whenever it changes on the connected GitHub branch. It was chosen because it matches William's standing setup across all his other projects — consistency across projects is explicitly worth more to him than picking the theoretically optimal host for this one folder.

AlternativeWhy it lost
GitHub PagesWould work fine for this — plain static HTML, no build step needed either way — but it is not William's cross-project standard, and consistency won.
Local Caddy serverFine for offline viewing on William's own machine, but produces no shareable URL, which defeats the point of a docs site other people can open.

Adoption trigger

T1 Before first user — per the brief's service table, this is adopted at T1, alongside App Check and Sentry, ahead of the rec-center beta rather than on day one.

It is T1 and not T0 because the docs are useful to William solo without a public URL; a shareable URL matters once someone else (a stakeholder, a tester, a future collaborator) needs to read these docs.

Setup steps

  1. In the Cloudflare dashboard, connect the GitHub repo Willpatbarr/ForgeByAlpfit.
  2. Set the build output directory to docs.
  3. Leave the build command empty — these are plain static HTML files, so no build step runs.
  4. Select main as the production branch, matching the repo's default branch.
  5. Do not change the output directory away from docs once a URL has been shared — changing it later breaks every link anyone has bookmarked.
  6. Verify: push a trivial change to any file under docs/, confirm a new Cloudflare Pages build triggers automatically, and open the deployed URL to confirm the change is live.

The docs/ folder contains no application secrets, since it is plain static HTML with no build step and no runtime config. Nothing here requires a .env.example entry, and real secrets are never committed to this repository regardless.
