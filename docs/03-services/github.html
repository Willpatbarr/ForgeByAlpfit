Forge docs / 03-services / GitHub

GitHub LOCKED T0 Now

What this is: where Forge's code and this docs/ folder live, and nowhere else — for how the project is planned, see linear.html.

What & why

GitHub hosts the private Forge repository — the source of truth for every line of Dart and every doc in this folder. It was chosen because it is where the repo already lives, has zero migration cost, and gives unlimited private-repo collaborators for free.

AlternativeWhy it lost
GitLabNo reason to move — repo already exists on GitHub, and moving is pure cost with no benefit.
Self-hosted git (Gitea, etc.)Adds server maintenance for a solo dev with zero users. Rejected as premature per the brief's service table.

Adoption trigger

LOCKED T0 Now — already adopted, not a future decision. The repo Willpatbarr/ForgeByAlpfit already exists, is private, has Issues enabled, and defaults to branch main.

It is T0 because the code has to live somewhere from day one; there is no lower tier for "where is the source code."

Setup steps

  1. Confirm the repo exists: Willpatbarr/ForgeByAlpfit, private, default branch main. It already does — this is a status check, not a creation step.
  2. Confirm Issues is enabled in repo settings. It is enabled, but per the brief, Issues stays empty on purpose — see below.
  3. Do not create GitHub Actions workflows yet. There is deliberately no .github/workflows directory in this repo right now — this is a scoped deferral (see §4 "Rejected as premature" in the decision brief: CI is adopted only when a second developer joins, or a broken build first reaches a tester), not an oversight.
  4. Keep docs/ in this same repo — it is what Cloudflare Pages will build from. See cloudflare-pages.html.
  5. Verify: run git clone https://github.com/Willpatbarr/ForgeByAlpfit.git into a scratch directory and confirm the Flutter source and docs/ both appear. If that clone works, GitHub is correctly set up as the code and docs home.
Painful to change later: the default branch name (main) and repo visibility (private) are cheap to change now, expensive once CI, branch protection rules, or external collaborators depend on them. Decide those before adding either.
